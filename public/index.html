«Камеры дома»: видеонаблюдение из обычного компьютера

Работает каждый день

Обычный компьютер с Windows 11 вместо видеорегистратора: записывает камеры, сам замечает людей и машины и показывает всё на телефоне.

Написал на Python сервер, который забирает потоки с камер в домашней сети, пишет их на диск и раздаёт через веб-интерфейс на React. Для настроек сделал отдельное окно программы с журналом событий и несколькими пользователями.

Самое интересное было дальше: как смотреть всё это с телефона, если провайдер не даёт белый IP, а VPN включать каждый раз лень. На пути встали три стены:

  • Белый IPего дома нет. Решение: домашний компьютер сам держит соединение с моим сервером в Москве, а тот открывает камеры по обычной ссылке.
  • Tailscaleс мобильного интернета не подключался. Решение: отказался от VPN, доступ идёт через тот же сервер с HTTPS.
  • Telegramуведомления туда не доходили. Решение: перевёл оповещения на «Алису» в Яндекс Станциях, ВКонтакте и бота в MAX.
  • РаспознаваниеОтличает людей и машины от веток и кошек — рамки на кадрах вверху настоящие.
  • Клип событияСохраняет 10 секунд до срабатывания и минуту после, чтобы было видно, откуда человек пришёл.
  • НочьюКамеры уходят в ИК-режим, распознавание продолжает работать.

RTSP Atom: видеостена для сети без интернета

Версия 1.1

Компьютер с Astra Linux «Смоленск», камеры в закрытой сети и ни одного байта интернета. Нужно, чтобы операторы смотрели камеры в браузере — и чтобы всё ставилось одной командой.

Привычное «apt install» тут не работает: каждую зависимость нужно найти, скачать заранее и положить в пакет. Поэтому RTSP Atom везёт с собой всё — и Node.js, и медиасервер MediaMTX. Распаковал архив, запустил install.sh, придумал пароль администратора — панель работает.

Камеры приходят по RTSP, RTMP, HLS, SRT или UDP, MediaMTX переупаковывает их в LL-HLS, и браузер показывает видео почти без задержки и без плагинов.

Сервер написан на чистом Node.js, без единой внешней библиотеки: HTTP, база SQLite и шифрование — из стандартной поставки. Меньше зависимостей — меньше того, что нужно тащить в закрытую сеть.

  • ВидеостенаОт 1×1 до 4×4, сохранённые раскладки, полноэкранный режим.
  • Роли и доступАдминистратор, оператор, наблюдатель. Ограничения по компьютерам и IP-адресам.
  • ЗащитаБелые и чёрные списки IP, блокировка перебора паролей, журнал действий с выгрузкой в CSV.
  • Проверка перед выпускомGitHub Actions собирает пакет, гоняет тесты, сквозной тест «камера → панель → видео» и пробную установку в чистой системе.

Свой мессенджер на Matrix: Synapse и Element

Работает

Переписка, которая не зависит ни от чьих блокировок и не лежит на чужих серверах.

Matrix — открытый протокол для обмена сообщениями. Поднять голый сервер несложно, а вот собрать всё, чтобы им было удобно пользоваться каждый день, — отдельная работа. Я развернул сервер Synapse полностью, со всеми службами, а не только ядро — и это хорошая замена публичным мессенджерам.

А потом взялся за клиент: настроил Element и переделал его мобильное приложение под свой сервер. Ничего не нужно вводить вручную — установил и сразу оказался дома.

  • Весь серверВсе службы развёрнуты и настроены, а не только базовый сервер.
  • Своё приложениеМобильный Element, доработанный под этот сервер.
  • Данные у себяПереписка хранится на собственном сервере.

Этот сайт

Вы на нём

Сообщение из формы внизу страницы приходит мне в MAX через секунду после отправки.

Сервер написан на чистом Python, без единой сторонней библиотеки. Он встал рядом с двумя другими сайтами на том же сервере и не задел их: HTTPS выдаёт Caddy, а каждый сайт живёт в своей папке.

Отдельное приключение — API MAX: он работает на сертификате Минцифры, которого нет в Ubuntu. Пришлось подключить его только для этого сайта, не трогая систему.
